# Линия «X-студия Shoulda Held» — требования для фабрики агентов

Версия 1 · 25 октября 2026 · владелец: Дмитрий

## 1. Зачем эта линия

Shoulda Held? (https://shouldaheld.com) — бесплатный «чек» для LP на Solana (Meteora DLMM): сколько из заработанных комиссий человек **сохранил** после движения цены (метрика *fees kept*). Плюс ежедневный рейтинг LP: https://shouldaheld.com/top.html.

Фаза 0 — собрать аудиторию и лист ожидания под фазу 1 (copy-LP: копирование позиций лучших LP с комиссией). Единственный канал — **X (@shouldaheld)**. Видео, YouTube и другие сети не делаем.

Задача линии — каждый день приводить LP из X на сайт, чтобы они проверили свой кошелёк, поделились чеком и встали в лист ожидания.

**Успех через 30 дней после запуска** (цифры смотрим в админке сайта):

| Метрика | Цель |
|---|---|
| Проверок кошельков в неделю | 300+ |
| Доля проверок своего кошелька (не пример) | 60%+ |
| Шерингов на 100 проверок | 10+ |
| Заявок в лист ожидания в неделю | 30+, из них 5+ «big LP» или «leader candidate» |
| Подписчики @shouldaheld | 1 000+ |

**Анти-цели** (провал, даже если цифры растут):
- нас воспринимают как скам или «сигнальный канал»;
- пост выглядит как совет купить токен или скопировать кошелёк;
- в посте неверная цифра;
- нас блокирует X за спам.

## 2. Входные данные

| Источник | Что там | Как получить |
|---|---|---|
| Рейтинг | Топ LP, зал позора, статистика пулов. Обновляется раз в сутки около 03:20 UTC. | `GET https://shouldaheld.com/data/leaderboard.json` |
| Чек любого кошелька | Полный расчёт по кошельку, ссылка годится для поста | `https://shouldaheld.com/?wallet=<адрес>` |
| Логика расчёта | Формулы и оговорки | https://shouldaheld.com/ → «How is this calculated?», код: `calc.js` в github.com/cozy-crypto/lp-report |
| Метрики сайта | Воронка, источники трафика, шеринги | Админка `admin.shouldaheld.com` закрыта Cloudflare Access. Для агентов отдельный эндпоинт со сводкой (см. п. 8). |

Формат `leaderboard.json`:

```json
{
  "updatedAt": "2026-10-25T21:18:06Z", "days": 365, "crawled": 136, "skipped": 209, "failed": 0,
  "wallets": [  // отсортированы по k, лучшие первыми
    { "w": "<адрес>", "k": 0.924, "fees": 3091, "lp": 2851, "pnl": 262, "dep": 30302,
      "pools": 26, "pos": 98, "top": ["KNOTS-SOL", "STONK-SOL", "SI-SOL"] }
  ],
  "pools": [   // отсортированы по fees
    { "address": "<адрес пула>", "name": "SOL-USDC", "lps": 12, "k": 0.568, "beat": 0.667, "fees": 51234, "lp": 20111 }
  ]
}
```

Расшифровка полей:
- **wallets:**
  - `k` — fees kept (0.92 = 92%);
  - `fees` — заработанные комиссии, $;
  - `lp` — чем ликвидность лучше простого холда тех же токенов, $;
  - `pnl` — итоговый результат кошелька, $;
  - `dep` — сколько всего внесено, $;
  - `pools` / `pos` — сколько пулов и позиций;
  - `top` — пулы, где заработано больше всего комиссий.
- **pools:**
  - `lps` — сколько LP мы видели в пуле;
  - `beat` — доля из них, обыгравших холд;
  - `k` — fees kept у медианного LP.

## 3. Доска: колонки

`Идея → Черновик → Проверка → Готово к публикации → Опубликовано → Итоги (через 48 ч)`

Дополнительная колонка: `Нужен человек` (Telegram владельцу).

Одна карточка — один пост или одна ветка. В карточке:
- рубрика;
- текст;
- источник цифр: какие поля и за какую дату `updatedAt`;
- ссылка;
- время публикации;
- после публикации — метрики.

## 4. Роли

### 4.1 Стратег (сильная модель, раз в день после обновления рейтинга)

- Читает свежий `leaderboard.json`, вчерашний рейтинг из git-истории фабрики, итоги прошлых постов и сводку метрик сайта.
- Создаёт 3–5 карточек в «Идея»: рубрика, главный факт, почему это интересно сегодня.
- Ищет **изменения**: кто вошёл в топ-10, кто упал, у какого пула резко изменилась доля LP, обыгравших холд, новые рекорды.
- Раз в неделю правит плейбук (п. 6) по итогам: какие рубрики и часы работают. Изменения — коммитом в базу знаний.

### 4.2 Райтер (средняя модель)

- Превращает идею в пост или ветку по шаблонам рубрик (п. 6) и голосу бренда (п. 5).
- Обязательно указывает в карточке, из каких полей взята каждая цифра.
- Ссылки только на shouldaheld.com: чек кошелька, рейтинг или главная.

### 4.3 QA (средняя модель + скрипт сверки)

Без отметки «прошло» публикация невозможна. Проверка:
1. **Цифры.** Скрипт пересчитывает каждую цифру из `leaderboard.json` с той же датой `updatedAt`. Допуск — округление, иначе возврат.
2. **Запрещённое** (п. 7) — скрипт со списком слов плюс проверка моделью по смыслу.
3. **Длина.** Не больше 280 символов на пост, ссылка работает (HTTP 200).
4. **Кошельки** только в коротком виде `7csV…6ivn`, полный адрес — только внутри ссылки на чек. Кошелька нет в `crawl/exclude.txt`.
5. **Тон.** Не высмеиваем человека, смеёмся над ситуацией. Зал позора — про цифры, а не про людей.

### 4.4 Публикатор (скрипт, модель не нужна)

- Публикует через X API из колонки «Готово к публикации» по расписанию.
- Слоты: 13:00, 16:00 и 20:00 UTC, не больше 3 постов в день.
- Добавляет UTM к ссылкам: `?utm_source=x&utm_campaign=<рубрика>` (для чека — `&utm_source=x`, параметр `wallet` сохраняется). По ним админка показывает, какая рубрика приводит людей.
- Следит за квотой X API. При исчерпании — в «Нужен человек».

### 4.5 Сторожа (скрипты без модели)

| Сторож | Что делает |
|---|---|
| Рейтинг | Каждый час проверяет `updatedAt`. Если рейтинг не обновился за 30 часов — Telegram: «сбор рейтинга упал». |
| Итоги | Через 48 часов после публикации собирает показы, лайки, репосты и клики по посту (X API) и визиты по UTM (п. 8), записывает в карточку и двигает её в «Итоги». |
| Упоминания | Если тариф X API позволяет поиск: раз в час ищет `shouldaheld.com` и `@shouldaheld`. Найденное — карточка «Ответить» (ответ пишет райтер). |
| Квота | Остаток лимита X API, предупреждение при 80%. |

### 4.6 Нужен человек (владелец, Telegram)

- Первые 10 постов линии — все через человека.
- Любой пост, где кошелёк связывается с конкретным человеком или X-аккаунтом.
- Ответы на жалобы и просьбы убрать кошелёк. Удаление: адрес добавляется в `crawl/exclude.txt` репозитория lp-report.
- Любая фраза про будущий copy-LP сверх утверждённой (п. 7).

## 5. Голос бренда

- **Английский язык**: аудитория — крипто-X.
- Коротко и сухо, с иронией. Маскот — енот, но в тексте без эмодзи-зоопарка, максимум 1 эмодзи на пост.
- Говорим как честный бухгалтер: «вот чек, вот цифры». Без хайпа, без «🚀», без «alpha».
- Главная мысль, которую повторяем: *your PnL includes the market — see what liquidity actually earned you.*
- Подпись бренда — «Shoulda held?» — только когда холд действительно выиграл.

## 6. Рубрики (шаблоны)

| Рубрика | Частота | Шаблон (суть) |
|---|---|---|
| **LP of the day** | ежедневно | «Today's best Meteora LP kept {k}% of ${fees} in fees after price moves. Most LPs keep {median}%. Receipt: {ссылка на чек}» |
| **Shoulda held** | 3 раза в неделю | «This LP earned ${fees} in fees and still lost ${-lp} to simply holding. Deposited ${dep}. Receipt: …» |
| **Pool truth** | 2 раза в неделю | «{pool}: {beat}% of LPs we tracked beat holding. The typical one kept {k}% of fees. Leaderboard: …» |
| **Weekly board** | понедельник | Ветка из 4–6 постов: топ-5, кто вырос и кто упал, лучший и худший пул, призыв «where would you rank?» со ссылкой на главную |
| **Explainer** | раз в неделю | Одна мысль про LP и холд с примером из чека: что такое fees kept, почему APR пула врёт, почему PnL включает рынок |
| **Reply** | по мере появления | Ответ в чужой ветке про LP или Meteora: одна цифра по делу плюс ссылка на рейтинг. Без спама: не больше 5 ответов в день, никогда не повторять один текст |

Закреплённый пост (пишет человек с райтером один раз): что такое Shoulda Held, пример чека, ссылка.

## 7. Запреты (жёсткие)

- **Никаких советов:**
  - «buy», «sell», «ape», «copy this wallet», «follow this LP», «guaranteed», «free money»;
  - никаких прогнозов цены;
  - никаких обещаний доходности.
- **Никаких призывов вкладываться** в конкретный пул или токен. Пул — только как факт из данных.
- **Про copy-LP можно ровно это:** «We're building copy-LP. Join the waitlist on shouldaheld.com.» Без сроков, комиссий и обещаний результатов.
- **Не связывать кошелёк с личностью.** Не писать, кто стоит за адресом, даже если это известно.
- **Не делать шилл-постов** токенов и не принимать оплату за посты.
- **Каждый пост с цифрами содержит ссылку на источник:** чек или рейтинг.
- **Не писать того, чего нет в данных:**
  - «за всё время» — если данные за 365 дней;
  - «все LP» — если это LP, которых мы отслеживаем.

## 8. Что нужно от сайта (делает разработка lp-report, не линия)

1. **`GET api.shouldaheld.com/stats?key=…`** — публичная для фабрики сводка без персональных данных за 1, 7 и 30 дней:
   - визиты по `utm_campaign`;
   - проверки, шеринги, заявки;
   - доля проверок своего кошелька.
2. **Подсчёт публикаций чеков в X без X API.** Когда кто-то вставляет ссылку `r.shouldaheld.com/…` в пост, X запрашивает превью (бот Twitterbot). Это фиксируется как «чек опубликован». Клики людей по ссылке уже считаются.
3. Карточка «Rank card» для LP из рейтинга (например, «#3 of 1,200 Meteora LPs»), чтобы райтер мог прикладывать картинку.

## 9. Ограничения и затраты

- **X API.** Перед запуском проверить текущие тарифы. Бесплатный уровень исторически позволял только ограниченную публикацию без поиска. Поиск упоминаний и сбор метрик постов — на платном уровне. Если платный уровень не берём, сторож «Упоминания» отключён, а итоги постов собираются только по UTM-визитам сайта.
- **Модели.** Стратег — сильная модель, 1 запуск в день. Райтер и QA — средняя модель. Публикатор и сторожа — без модели.
- **Расход.** Ориентир — до 15 запусков модели в день.

## 10. Пилот

Неделя 1:
- все посты через «Нужен человек»;
- ежедневный разбор: какие рубрики дали визиты и проверки.

Неделя 2:
- без человека публикуются рубрики, у которых за неделю не было ни одной правки QA или человека;
- остальные — по-прежнему через человека.
