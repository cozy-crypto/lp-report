# Линия «X-студия Shoulda Held» — требования для фабрики агентов

Версия 2 · 26 октября 2026 · владелец: Дмитрий

## 1. Зачем эта линия

Shoulda Held? (https://shouldaheld.com) — бесплатный «чек» для LP на Solana (Meteora DLMM). Он показывает, сколько из заработанных комиссий человек **сохранил** после движения цены (метрика *fees kept*). На сайте также:
- ежедневный рейтинг LP: https://shouldaheld.com/top.html;
- дуэль двух кошельков;
- лист ожидания с реферальной очередью.

Фаза 0 — собрать аудиторию и лист ожидания под фазу 1. Фаза 1 — copy-LP: копирование позиций лучших LP за долю комиссии, это будущий доход.

**Канал — только X (@shouldaheld).** Видео публикуем внутри X. Telegram, Discord, YouTube и другие сети пока не трогаем.

**Главная цель линии:** заявки в лист ожидания от LP с реальными деньгами. Всё остальное — промежуточные метрики.

### Цели на 30 дней

Проверяет стратег по данным `/stats` (п. 2):

| Метрика | Цель | Поле в `/stats` |
|---|---|---|
| Заявки в лист ожидания | 150 всего, из них 25+ big LP или leader candidate | `waitlist.total`, `waitlist.bigLps`, `waitlist.leaderCandidates` |
| Проверки своего кошелька в неделю | 300+ | сумма `daily[].ownWalletChecks` за 7 дней |
| Чеки, реально опубликованные пользователями, в неделю | 30+ | сумма `daily[].cardsPosted` |
| Вирусный коэффициент: визиты из чужих чеков на одну проверку | 0,3+ | `visitsFromShares / checks` |
| Заявки по рефералке | 20%+ от всех | `waitlist.referred / waitlist.total` |

**Анти-цели** — провал, даже если цифры растут:
- нас считают скамом или «сигнальным каналом»;
- пост выглядит как совет купить токен или скопировать кошелёк;
- в посте неверная цифра;
- X ограничил аккаунт за спам или за массовые упоминания.

## 2. Данные

| Источник | Что там | Как получить |
|---|---|---|
| Рейтинг | Топ LP, «shoulda held», статистика пулов. Обновляется раз в сутки, около 03:20 UTC плюс время сбора. | `GET https://shouldaheld.com/data/leaderboard.json` |
| Аналитика сайта | Вся воронка по дням, источники, кампании, шеринги, рефералка. Без персональных данных. | `GET https://api.shouldaheld.com/stats`, заголовок `Authorization: Bearer <STATS_KEY>` (ключ выдаёт владелец) |
| Чек любого кошелька | Полный расчёт | `https://shouldaheld.com/?wallet=<адрес>` |
| Логика расчёта | Формулы и оговорки | https://shouldaheld.com/ → «How is this calculated?»; код `calc.js` в github.com/cozy-crypto/lp-report |
| Результаты своих постов | Показы, лайки, репосты, ответы | X API, платное чтение (п. 9) |

### `leaderboard.json`

```json
{
  "updatedAt": "2026-10-25T21:18:06Z", "days": 365, "crawled": 136, "skipped": 209, "failed": 0,
  "wallets": [ { "w": "<адрес>", "k": 0.924, "fees": 3091, "lp": 2851, "pnl": 262, "dep": 30302,
                 "pools": 26, "pos": 98, "top": ["KNOTS-SOL", "STONK-SOL", "SI-SOL"] } ],
  "pools":   [ { "address": "<адрес пула>", "name": "SOL-USDC", "lps": 12, "k": 0.568, "beat": 0.667, "fees": 51234, "lp": 20111 } ]
}
```

Поля `wallets` (отсортированы по `k`, лучшие первыми):
- `k` — fees kept, 0.92 = 92%;
- `fees` — заработанные комиссии, $;
- `lp` — насколько ликвидность лучше холда тех же токенов, $;
- `pnl` — итоговый результат, $;
- `dep` — сколько внесено, $;
- `pools` / `pos` — число пулов и позиций;
- `top` — пулы, где заработано больше всего комиссий.

Поля `pools`:
- `lps` — сколько отслеживаемых LP в пуле;
- `beat` — доля тех, кто обыграл холд;
- `k` — fees kept медианного LP.

### `/stats`

- `daily[]` — по дням за 30 дней, новые первыми:
  - `visits` — визиты;
  - `visitsFromShares` — визиты из чужих чеков;
  - `checks` — проверки;
  - `walletsChecked` — уникальные кошельки;
  - `ownWalletChecks` — проверки своего кошелька, а не примера или чужой ссылки;
  - `failedChecks` — неудачные проверки;
  - `shares` — нажали «Share»;
  - `cardsPosted` — X или другая площадка подтянула превью, то есть ссылка реально опубликована;
  - `shareClicks` — клики по опубликованным чекам;
  - `signups` — заявки;
  - `referredSignups` — заявки по рефералке;
  - `avgCheckMs` — среднее время проверки.
- `sources` и `campaigns` — визиты за 7 дней по `utm_source` или сайту-источнику и по `utm_campaign`.
- `shares` — шеринги по типу карточки:
  - `receipt` — обычный чек;
  - `rank` — «TOP 12% of Meteora LPs»;
  - `duel` — «я против @друга».
- `cards[]` — топ-20 карточек недели: где опубликована, сколько кликов, сколько проверок она принесла.
- `feesKeptBuckets`, `depositBuckets` — кто проверяет: по fees kept и по размеру вложений.
- `waitlist` — всего, кто чего хочет, big LP, leader candidates, сколько по рефералке.
- `actions` — нажатия на сайте: дуэли, скачивания, вкладки рейтинга, копирование реферальной ссылки.

## 3. Доска

Основной поток:
`Идея → Черновик → Проверка → Готово к публикации → Опубликовано → Итоги (через 48 ч)`

Отдельно:
- `Нужен человек` — Telegram владельцу;
- `Стратегия` — одна постоянная карточка с текущим планом недели, её ведёт стратег.

Одна карточка — один пост, ответ или ветка. В карточке:
- рубрика и гипотеза, которую пост проверяет;
- текст;
- источник каждой цифры: поле и дата `updatedAt`;
- ссылка с UTM;
- время публикации;
- после публикации — метрики.

## 4. Стратег — главная роль линии

Сильная модель. Запуск раз в день после обновления рейтинга, около 05:00 UTC, плюс разбор недели по понедельникам. Стратег не пишет посты: он решает, **что** делать и **почему**, и меняет план, если цифры говорят, что он не работает.

### 4.1 Ежедневный цикл

1. **Собрать картину:**
   - `/stats` — вчера и последние 7 дней;
   - свежий и вчерашний `leaderboard.json`, вчерашний — из истории git фабрики;
   - итоги постов за 48 часов, колонка «Итоги»;
   - текущая карточка «Стратегия».
2. **Сравнить с целью (п. 1):**
   - на каком шаге воронки мы теряем больше всего: визит → проверка → шеринг → публикация → клик → заявка;
   - в темпе ли мы к цели на 30 дней.
3. **Найти, что сработало:**
   - какие `utm_campaign` и рубрики дали проверки и заявки, а не лайки;
   - какой тип карточки чаще реально публикуют: `cardsPosted / shares` по `kind`.
4. **Решить:**
   - 3–5 карточек «Идея» на сегодня, у каждой рубрика, гипотеза и `utm_campaign`;
   - 1–3 карточки «Блогер» (п. 5.2), если есть подходящие кандидаты;
   - что убрать: рубрику без проверок за 7 дней — сократить вдвое; за 14 дней — заменить экспериментом.
5. **Записать:** обновить карточку «Стратегия» — что видим, что меняем, почему. Изменения правил — коммитом в плейбук (п. 6), чтобы они были видны в истории.
6. **Отчёт в Telegram владельцу**, 5 строк: цифры вчера против цели, главное наблюдение, что меняем, что нужно от человека.

### 4.2 Правила решений

- **Оптимизируем заявки и проверки своего кошелька, а не лайки.** Пост с тысячей лайков и нулём проверок — неудачный.
- **Узкое место важнее всего.** Если люди проверяют, но не делятся — посты, которые показывают, как выглядит красивый чек (rank, duel). Если делятся, но заявок нет — посты про copy-LP-очередь и рефералку.
- **Эксперимент — 20% слотов.** Каждую неделю одна новая рубрика или формат, оценка через 7 дней.
- **Сигнал о проблеме с продуктом.** Если `failedChecks` выше 5% проверок или `avgCheckMs` больше 30 000 — карточка «Нужен человек»: это проблема сайта, а не контента.
- **Предложения по продукту.** Если видишь, что не хватает функции (новый тип карточки, рубрика на сайте) — карточка «Нужен человек» с предложением. Сайт меняет разработка, не линия.

### 4.3 Еженедельный разбор (понедельник)

- Неделя против цели по всем метрикам п. 1.
- Топ-3 и худшие 3 поста по проверкам.
- Что меняем в плейбуке.
- Нужно ли просить у владельца бюджет на X API.
- Текст рубрики «Weekly board» для райтера.

## 5. Остальные роли

### 5.1 Райтер (средняя модель)

- Пост или ветка по шаблону рубрики (п. 6) в голосе бренда (п. 7).
- Видео-пост: сценарий клипа на 10–20 секунд. Запись экрана: вставили кошелёк → чек печатается → крупно FEES KEPT. Ферма собирает клип своим продюсерским инструментом. Публикуется только в X.
- Каждая цифра — со ссылкой на поле данных.
- Ссылки только на shouldaheld.com, всегда с UTM: `utm_source=x&utm_campaign=<рубрика>-<дата>`.

### 5.2 Скаут блогеров (средняя модель + X API на чтение)

Задача — найти людей, которые **сами** публично показывают свой Solana-кошелёк и хвастаются LP-результатами, и подготовить им ответ с их чеком. Это главный рычаг роста.

1. **Поиск, до 100 постов в день** (бюджет чтения, п. 9). Запросы: `meteora dlmm`, `LP pnl`, `my LP position`, `solscan.io/account`, `app.meteora.ag` — за последние 48 часов, авторы с 1 000+ подписчиков.
2. **Отбор.** В посте или в профиле автора есть адрес кошелька, который **он сам** опубликовал как свой. Чужие адреса, адреса из ответов и «угаданные» кошельки — нельзя.
3. **Проверка.** Открыть `?wallet=<адрес>`. Если позиций нет или комиссий меньше $100 — отказ.
4. **Карточка «Блогер»:**
   - ссылка на исходный пост;
   - адрес;
   - цифры чека;
   - черновик ответа от райтера.
5. **Ответ публикует только человек** после проверки в колонке «Нужен человек». Тон — уважительный, без насмешки даже при плохом результате: «You're up $40k — nice. Of that, liquidity itself added $X after price moves, the rest was the market. Full receipt: …». Не больше 3 ответов блогерам в день, одному автору — не чаще раза в 30 дней.

### 5.3 QA (средняя модель + скрипт сверки)

Без отметки «прошло» публикации нет. Проверки:
1. **Цифры.** Скрипт пересчитывает каждую из `leaderboard.json` с той же `updatedAt` или из чека. Допуск — округление.
2. **Запреты (п. 8)** — скрипт со списком слов плюс модель по смыслу.
3. **Ссылки и длина.** Не больше 280 символов на пост; ссылка отвечает 200; UTM на месте.
4. **Кошельки.** В тексте только короткий вид `7csV…6ivn`. Кошелька нет в `crawl/exclude.txt`. У блогера — адрес совпадает с тем, что он сам опубликовал.
5. **Тон.** Смеёмся над ситуацией, не над человеком.

### 5.4 Публикатор (скрипт)

- Публикует через X API по расписанию: не больше 3 своих постов в день, слоты 13:00, 16:00 и 20:00 UTC; ответы — отдельно, по одобрению.
- Ссылку можно ставить в первый ответ к посту, а не в сам пост: X хуже показывает посты со ссылками. Как лучше — решает стратег по итогам.
- Следит за бюджетом X API, при 80% — в «Нужен человек».

### 5.5 Сторожа (скрипты)

| Сторож | Что делает |
|---|---|
| Рейтинг | Если `updatedAt` старше 30 часов — Telegram «сбор рейтинга упал». |
| Итоги | Через 48 часов после публикации: метрики поста из X API плюс визиты и проверки по его `utm_campaign` из `/stats` → в карточку, карточка → «Итоги». |
| Упоминания | Раз в 2 часа: поиск `shouldaheld` и `@shouldaheld` (в рамках бюджета). Новые → карточка «Ответить». |
| Рекорды | Новый №1 рейтинга, кошелёк с `dep` ≥ $1M в топ-10, пул с `beat` ниже 30% → карточка «Идея» для стратега. |

### 5.6 Нужен человек (владелец, Telegram)

- Первые 10 постов линии.
- Все ответы блогерам (п. 5.2).
- Любой пост, где кошелёк связывается с человеком или аккаунтом.
- Жалобы и просьбы убрать кошелёк → адрес в `crawl/exclude.txt` репозитория lp-report.
- Любая фраза про copy-LP сверх разрешённой (п. 8).
- Сигналы стратега о проблемах сайта и предложения по продукту.

## 6. Рубрики (стартовый плейбук, его правит стратег)

| Рубрика | Частота на старте | Суть |
|---|---|---|
| **LP of the day** | ежедневно | «Today's best Meteora LP kept {k}% of ${fees} in fees after price moves. Most LPs keep {median}%. Receipt: …» |
| **Shoulda held** | 3 раза в неделю | «Earned ${fees} in fees, still lost ${-lp} to simply holding. Deposited ${dep}. Receipt: …» |
| **Pool truth** | 2 раза в неделю | «{pool}: only {beat}% of LPs we track beat holding. The typical one kept {k}% of fees.» |
| **Receipt clip** | 2 раза в неделю | Видео 10–20 секунд: кошелёк → чек → FEES KEPT. Подпись в одну строку и ссылка. |
| **Rank / duel bait** | 2 раза в неделю | Призыв показать свой ранг или вызвать друга: «Drop your TOP % below» / «Tag the LP friend you think keeps more fees» со ссылкой на главную. |
| **Waitlist** | раз в неделю | Сколько людей в очереди, как работает рефералка (каждый приведённый поднимает на 10 мест). Без обещаний о copy-LP (п. 8). |
| **Weekly board** | понедельник | Ветка: топ-5, кто вырос и кто упал, лучший и худший пул, «where would you rank?» |
| **Explainer** | раз в неделю | Одна мысль: что такое fees kept, почему APR пула врёт, почему PnL включает рынок. |
| **Blogger reply** | до 3 в день | См. п. 5.2. |

Закреплённый пост — один раз, пишет человек вместе с райтером: что это, пример чека, ссылка.

## 7. Голос бренда

- **Язык — английский.** Коротко и сухо, с иронией. Как честный бухгалтер: «вот чек, вот цифры».
- **Маскот — енот.** В тексте не больше 1 эмодзи; никаких «🚀», «alpha», «LFG».
- **Главная мысль:** *your PnL includes the market — see what liquidity actually earned you.*
- **«Shoulda held»** пишем только когда холд действительно выиграл.

## 8. Запреты (жёсткие)

- **Никаких советов:**
  - «buy», «sell», «ape», «copy this wallet», «follow this LP», «guaranteed», «free money»;
  - никаких прогнозов цены;
  - никаких обещаний доходности.
- **Никаких призывов вкладываться** в конкретный пул или токен.
- **Про copy-LP можно только:** «We're building copy-LP. Join the waitlist on shouldaheld.com.» и место в очереди. Без сроков, комиссий и результатов.
- **Не связывать кошелёк с личностью.** Исключение — кошелёк, который человек сам публично назвал своим (п. 5.2), и только в ответе ему же.
- **Без массовых упоминаний.** Не тегать людей, которые не писали о своих LP-результатах. Не больше 3 упоминаний блогеров в день — иначе X ограничит аккаунт.
- **Не шиллить** токены, не брать оплату за посты.
- **Каждая цифра — со ссылкой** на чек или рейтинг.
- **Только то, что есть в данных:**
  - «за 365 дней», а не «за всё время»;
  - «LP, которых мы отслеживаем», а не «все LP».

## 9. X API и затраты

С февраля 2026 X API работает по предоплате за каждый запрос, бесплатного уровня для новых разработчиков нет. Ориентиры по сторонним обзорам — перед запуском сверить с официальной консолью X:
- публикация поста — около $0,015;
- публикация поста **со ссылкой** — около $0,20;
- чтение поста — около $0,005.

**Бюджет на старт:** до $60 в месяц.
- Публикации: 3 поста в день, в основном со ссылкой ≈ $20.
- Чтение: скаут — 100 постов в день плюс сторож упоминаний и итоги ≈ $25–35.

Если бюджета нет, скаут и сторож упоминаний выключены, а итоги постов считаются только по UTM из `/stats`.

**Модели:**
- стратег — сильная, 1 запуск в день плюс еженедельный;
- райтер, скаут, QA — средняя;
- публикатор и сторожа — без модели.

## 10. Пилот

- **Неделя 1:** всё через «Нужен человек». Стратег работает с первого дня и шлёт ежедневный отчёт.
- **Неделя 2:** без человека публикуются рубрики, где за неделю не было ни одной правки QA или человека. Ответы блогерам — всегда через человека.
- **Итог пилота:** стратег пишет владельцу, сколько заявок и проверок принесла каждая рубрика и что делать дальше.
